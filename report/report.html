4. The agents

The system uses small, bounded components. Each model output is treated as untrusted data and is validated before it can affect the application.

Components and allowed tools

  • Chat splitter — code: parses supported timestamps and senders, attaches continuation lines to the previous message, applies limits, and reports skipped or truncated lines. It uses no model tools.
  • Attendance agent — model: receives numbered message indexes and text plus roster names and aliases; returns only schema-validated attendance claims. It uses only the centralized model client.
  • Claim resolver — code: resolves exact names and aliases, applies only the latest self claim, flags third-party and mass claims, and creates pending guests without ratings. It uses no model tools.
  • Claim verifier — code: checks message indexes, verbatim evidence, allowed statuses, and forbidden extra fields. It uses no model tools.
  • Organizer confirmation — human control: reviews and edits proposed attendance, confirms the squad, and types guest ratings. It is not an autonomous agent.
  • Draw engine — code tool: `fairdraw.draw.draw()` creates teams from the confirmed roster, settings, history, and seed. It uses no tokens and no model tools.
  • Draw verifier — code: checks attendance coverage, unknown names, team-size balance, and seed replay. It uses no model tools.
  • Announcement agent — model: receives only the public receipt and sanitized organizer note, then writes a short announcement. The code appends the exact seed, draw number, and hash.
  • Announcement verifier — code: checks names and numbers against the allowed receipt data; after one retry it shows a code-generated fallback if needed.
  • Optional assistant agent — organizer-only model: may plan only these allowlisted calls: `propose_attendance(chat_text)`, `set_status(player, status)`, `add_guest(name)`, `confirm_attendance()`, `run_draw(num_teams, seed_mode)`, `verify_draw()`, `write_announcement(note)`, and `save_night()`. Code validates and executes calls one at a time, with approval for saved-state changes.

6. Safety

What could go wrong

Chat can contain prompt-injection text or attempts to game attendance. A model can invent a player, quote, rating, or action. An organizer command could request an unsupported roster edit or create a loop. Repeated clicks or malformed input could overspend. Private ratings and real player data could also leak into public outputs.

Controls built into the system

Messages are separated from instructions and sanitized. The schema has no team or rating fields. Code parses timestamps and senders, resolves exact names and aliases, rejects mass claims and unknown names, keeps third-party claims pending confirmation, and gives guests no rating until the organizer enters one. The draw is code-only and cannot run before confirmation. Claims, draws, and announcements have separate verifiers. The model gateway has timeout/retry limits, application caching, and per-run, session, and daily budgets. Public receipts omit private ratings.

Evidence that defenses work

The attack, malfunction, and overspending suites reported 7 passed in the recorded targeted run. 8. Limits + next steps

The labeled evaluation contains real errors, not just abstract risks. Source: results/eval_errors.md. The recorded run produced 100 error entries across five runs; examples include expected “self/in”, “self/out”, “self/maybe”, “self/late”, guest, and third-party claims being returned as empty by the model.

Ratings are subjective inputs. Outsiders cannot independently replay the draw without the organizer’s private ratings and full receipt inputs. An organizer could still bias the result by editing attendance, ratings, or the roster before confirmation. One league night would be a small sample, and the simulation uses a small sample roster with simulated attendance.

The project also lacks completed real token and cost experiments because the safety budgets correctly refused them. Screenshot evidence for verification states, token usage, fallback behavior, and some draw states is still incomplete.

Next month: complete a permissioned real-night study; improve the attendance prompt and evaluate it against reviewed labels; complete a budget-approved cost comparison; add independent organizer/auditor review; improve the evidence capture flow; and test the public receipt verification process with an outside reviewer.
